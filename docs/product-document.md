# CowAgent 原生 macOS 产品文档

> 文档版本：1.0
>
> 适用产品：本 fork 在单台 macOS 上原生安装、由当前用户长期运行的 CowAgent
>
> 当前形态：单用户、本地优先、完整 Agent 能力、Web 控制台与个人微信双通道

## 1. 产品定义

CowAgent 是一个属于个人、长期运行在本机上的 AI Agent。它不是只提供聊天窗口的问答工具，而是可以在用户授权范围内读写文件、执行命令、操作浏览器、维护长期记忆、组织知识、安装技能、运行定时任务，并通过 Web 控制台或个人微信持续服务的个人助理。

本 fork 当前产品形态的核心特点是：

- **本地优先**：源码、运行时、数据和 Agent 工作区都在当前 Mac 上。
- **单用户长期运行**：面向一名主要使用者，不提供多租户或账号体系。
- **双入口**：Web 控制台与个人微信共享同一个 Agent 实例和数据。
- **完整本机能力**：可以使用终端、文件、浏览器、Node/MCP 与网络资源。
- **可持续使用**：配置、会话、记忆、知识、技能和产物在重启后保留。
- **可恢复运维**：`launchd` 自动恢复、每日备份、日志轮转和脚本化升级。

## 2. 产品目标

### 2.1 用户目标

1. 在一台 Mac 上完成安装后，通过本机 Web 控制台快速开始使用。
2. 能在手机上通过个人微信继续使用同一个 AI 助理。
3. 让 Agent 记住长期偏好和知识，而不是每次从零开始。
4. 让 Agent 能真正执行任务，包括操作本机文件、终端和浏览器。
5. 不依赖 Docker、Kubernetes、公网服务器或多用户平台即可长期运行。
6. 出现进程退出、Mac 重启或数据损坏时，有明确的恢复路径。

### 2.2 产品成功标准

- 安装脚本可重复执行，Web 健康检查通过，且不会自动弹出浏览器。
- 用户配置模型 Key 后，Web 与微信都能完成真实对话。
- 服务重启后配置、会话、记忆、微信会话和工作区数据仍然存在。
- 每日备份成功，归档权限正确，保留策略有效。
- Agent 能完成一次浏览器页面加载、文件读写和命令执行任务。
- 本地 Git 提交不会再次携带浏览器缓存或超大二进制文件。

## 3. 目标用户与场景

### 3.1 主要用户

**个人开发者/高阶个人用户**：

- 使用 macOS 作为主要工作机。
- 希望 AI 能直接访问自己的工作目录、代码仓库和浏览器。
- 重视数据留在本机，但不要求容器或独立用户级隔离。
- 接受 Agent 在当前 macOS 账户权限范围内操作。
- 能通过 Web 控制台配置模型，能完成微信扫码和基本终端操作。

### 3.2 核心使用场景

| 场景 | 用户目标 | 产品能力 |
| --- | --- | --- |
| 日常问答与规划 | 快速获得分析和方案 | Web/微信对话、模型切换、流式输出 |
| 本机任务执行 | 让 AI 真正操作文件和命令 | 终端、文件读写、浏览器、权限控制 |
| 长期个人助理 | 记住偏好、项目和知识 | 记忆、知识库、技能、工作区 |
| 多项目工作 | 不同项目避免文件互相干扰 | 会话级项目工作空间 |
| 移动端接续 | 离开电脑后继续使用 | 个人微信 iLink 通道 |
| 定时提醒与任务 | 让 Agent 按计划执行 | 定时任务、主动消息 |
| 本地资料整理 | 把文档和网页整理成知识 | 文件读取、网页抓取、知识库 |
| 长期稳定运行 | 重启后仍可恢复 | `launchd`、备份、日志轮转 |

### 3.3 非目标用户

- 需要多租户、组织权限、审计或计费平台的团队。
- 需要跨机器高可用和水平扩展的生产服务。
- 无法接受本机账户级访问权限的用户。
- 期望在 Mac 睡眠期间仍保持 7×24 在线的用户。

## 5. 用户旅程

### 5.1 首次安装

1. 执行项目安装脚本。
2. 脚本建立 Python/Node/Playwright/ffmpeg 运行时和两个 LaunchAgent。
3. 用户访问本机 Web 控制台并输入自动生成的密码。
4. 用户配置模型厂商、模型和 API Key。

### 5.2 首次对话

1. 新建 Web 会话。
2. 输入自然语言任务。
3. Agent 规划并调用所需工具。
4. 结果以流式回复、文件卡片或产物形式返回。

### 5.3 微信接入

1. Web 控制台进入「通道」。
2. 选择微信并扫码。
3. 手机确认后通道进入已登录状态。
4. 微信中出现机器人助手，可直接发送文本、图片、文件或视频消息。

### 5.4 日常使用

- 通过 Web 做复杂任务、文件操作和项目管理。
- 通过微信做移动端问答、转发资料和轻量任务。
- 通过知识库、记忆和 Skills 逐步积累个性化能力。

### 5.5 故障与恢复

- 进程异常：`launchd` 自动拉起。
- Mac 重启：用户登录后服务自动启动。
- 配置/数据误删：从每日备份恢复。
- 微信 session 失效：重新扫码。
- 升级失败：更新脚本回到旧 commit 并恢复服务。
- 大文件误提交：本地钩子拦截；未推送历史按运维手册清理。

## 7. 非功能需求

### 7.1 安全与隐私

- Web 只监听回环地址，必须使用随机密码。
- 配置、凭证、日志、备份权限仅当前用户可读写。
- API Key、Web 密码和微信凭证不得进入源码或 Git。
- 业务数据、配置和日志落盘在当前 Mac；对话内容、附件及工具参数会按功能发送给模型厂商、微信 iLink、搜索/抓取和 MCP 服务。
- 本 fork 未默认启用外部遥测或统计上报；运行指标以本机检查和运维记录为准。
- Agent 为 `full-access`，安全边界依赖用户对本机任务和第三方 Skill/MCP 的信任判断。
- 备份未加密，必须按敏感数据保管。

### 7.2 可靠性

- 服务异常退出后自动重启，并通过 `ThrottleInterval` 限制频繁重启。
- 升级失败必须回到更新前 commit 并恢复旧服务。
- 配置文件采用原子写入；浏览器缓存、数据和源码目录分离。
- 不承诺 Mac 睡眠期间的在线率或定时任务准时执行。

### 7.3 兼容性

- 目标系统：当前 macOS 用户环境。
- Python：3.13；Node：24 LTS；浏览器：Playwright Chromium。
- 个人微信客户端：8.0.69 或更高。
- 模型厂商通过统一模型层接入，主对话与视觉、语音、图像、向量能力可独立配置。

### 7.4 性能与容量

- 单用户、单进程、单机容量，不提供水平扩展。
- 首字延迟和任务耗时取决于模型、网络、上下文长度和工具调用次数。
- 浏览器、Node/MCP 子进程和 SQLite 会话库共享本机 CPU、内存和磁盘。
- Web 上传单次总大小上限为 512 MB。

### 7.5 可维护性

- 安装、更新、维护脚本必须幂等。
- 变更必须通过测试、静态检查、Git 大小检查和服务健康检查。
- 日志、备份、数据路径和安装事件有明确文档。
- 本地钩子和 CI 防止再次引入超大生成文件。

## 8. 产品边界与风险

| 风险 | 影响 | 当前缓解 |
| --- | --- | --- |
| `full-access` Agent | 可读取、修改或外传本机数据 | 本机单用户、会话级权限、只使用可信 Skill/MCP |
| 提示注入/恶意网页 | Agent 可能被诱导执行危险操作 | 限制提示边界、敏感操作前确认、使用低权限会话 |
| 微信 24 小时主动消息限制 | 超时后定时推送失败 | 用户重新发消息恢复 |
| Mac 睡眠 | 服务、微信和定时任务离线 | 唤醒后自动恢复；不承诺睡眠期在线 |
| 模型厂商故障 | 对话和工具规划中断 | 配置备用模型，查看日志和厂商状态 |
| 微信 session 过期 | 微信通道停止 | 自动清凭证并重新扫码 |
| 备份未加密 | 归档泄露风险 | 本机私有目录、`600` 权限、不外传 |
| 每日备份间隔 | 最坏丢失约一天数据 | 重要变更前手动备份 |
| 单机单进程 | 无高可用和横向扩展 | 明确定位为个人本地产品 |
| 大文件误提交 | 推送被 GitHub 拒绝 | pre-commit/pre-push/CI 三层拦截 |
| 第三方服务数据处理 | 对话、附件和工具参数会离开本机 | 只配置可信厂商与服务，敏感任务使用低权限会话 |

## 9. 验收标准

### 9.1 安装验收

- 安装脚本退出码为 0。
- `launchd` 主服务为 `running`，备份任务已加载。
- `/api/health` 返回 `{"status":"ok"}`。
- 只监听 `127.0.0.1:9899`。
- Web 密码登录成功，认证 Cookie 有效。
- 启动和重启不自动打开浏览器。

### 9.2 能力验收

- 模型 Key 配置后 Web 对话成功。
- 微信扫码后个人微信对话成功。
- Playwright Chromium 可加载测试页面。
- Node 24 的 `node`/`npx` 在 CowAgent 环境中可用。
- 文件读写、终端命令和浏览器工具至少各完成一次受控测试。

### 9.3 运维验收

- 服务重启后配置、会话和工作区数据仍存在。
- 手动维护任务生成可恢复备份。
- 备份文件 `600`、目录 `700`，保留策略符合预期。
- 日志轮转不会破坏当前日志。
- 本地 Git 钩子能拦截大文件和运行时缓存。
- 远程更新演练后仍能通过健康检查或成功回退。
